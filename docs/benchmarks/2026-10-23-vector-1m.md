## 0. 结论（先读这个）

四类"1M 外推"全部换成直测，门 2a 的条件判定债清偿：

1. **构建**：wrapper 全链路 1M 名义吞吐 **83.3/s**（3h20m29s）=
   引擎直连 1M（76.4/s）的 1.09x——集成零额外劣化；对 100k 图路径
   （217/s）=38%，字面触"60% 红线"，但衰减与 spike 已直测的引擎级
   衰减（129→76.4=59%）一致，**属 HNSW 规模项，非回归**。摄入接受
   5,938/s（seal 吃掉 78% 墙钟）。**压缩档 seal 停顿 1M 级 p50
   11.47s/max 26.27s（12 次）**——最重的结构信号，建议立项。
2. **查询**：recall 0.9480/0.9900/1.0000，graph/state p50 比值
   1.02-1.05x（线 1.2x ✓）。**ef64 p99 12.16ms 超 spec §6.3 的 10ms
   线 22%**（1M 首测该线）——建议项：ef 预算重校。满尾 vs 空尾差
   在噪声内：v0.11.3 尾扫快路在 1M 使尾成本可忽略（微基准结论不受
   影响）。
3. **重启**：mode A 纯森林加载 **open 8.728s + ready 0s**（红线
   10min，裕度 ~68x ✓）；mode B 链重放 open 7.2s + ready 3m9s
   （45,567 链向量，成本∝链字节）；无森林重建 ~3-4h（速率直测
   126.2/s + 下界 102.3min，以阶段 A 排水 3h17m40s 为同工作量参照）
   ——v.vec 在 1M 级是决定性的。**新发现：轻量 Close 后重开突发
   构建库，overlay 恢复冻结积压 970,751 条、ready 2h57m30s**——
   256MiB 阈值界住重放字节、界不住重打包工作量（B1 直测+冒烟双复
   现），建议单独立项。
4. **内存**：graph-alone **6.59GB**（2.14x 原始字节，含 props+森林
   两份向量，数据模型使然）；GC 停顿全程 16.3ms、占比可忽略——
   spec §12 的 GC 忧虑注记可销。State 级 1M 放大仍无直测（口径
   限制，见 §4 诚实备注）。

红线汇总：加载 ✓ 远优；构建按协议匹配口径压线（59%）、按字面口径
触线——如上归因；超线项（ef64 p99、压缩停顿、冻结积压）均为
**记录并建议、不修**，候选立项清单见各节。

## 方法要点与 harness 设计

- 摄入走真实 wrapper（`writer.Attach`+`Submit`，batch 256，CP 64MiB），
  逐 Submit 采样 `WALSize()`：落差 ≥ CP/2 判 seal，归属为下一个 Submit
  的排队等待（cadence harness 同款口径）。
- seal 分档只用公开行为：**快照名集合变化 = 压缩档**（压缩档必写新
  `<lsn>` 命名快照并 Reset 链；轻量档从不写快照）。bulk 卷（64×1MiB
  大属性节点）的压缩判定必须用快照集对比而非 WALSize 落差——一次
  bulk Submit 就是一个 seal，前后采样都在 seal 之后（≈0），落差不可
  见（smoke 实证：压缩已发生、盘上快照已落，落差检测器漏报）。
- n=1,001,471：n%2048=2047，收敛后 overlay 尾部恰好**满尾**（D7 读己
  写），与 v0.11.3 尾扫快路的满尾工况对齐。
- 查询协议修正 #4：真值前置不计时、查询连续计时、同会话直连 State
  参照；本跑参照 State 与图同种子同 pack 节奏并发构建（尾 2047 天然
  对齐，无需 100k 那次的重加尾部步骤）；空尾配对 = 参照 `Pack(true)`
  后复测。
- 重启三口径 + 附加的最坏工况（见下）。

## 冒烟发现（20k/CP=1MiB，管线验证副产品，已编入 harness 设计）

1. **森林缓存冻结的是"段+overlay"整体**：压缩时刻 overlay 里有多少
   未打包向量，重启就原样恢复多少并重付打包。smoke 两次独立复现：
   链拷贝重开 overlay-at-open=85536，原库重开同样 85536——恰为冻结时
   刻的积压。推论（1M 正式验证见 B1）：**突发摄入 + 轻量 Close 后重
   开，256MiB 保留阈值界住的是 WAL 重放字节，不是重打包工作量**。
2. WAL 段文件按 64MiB 预分配（`wal-<N>.log` 恒 67108864 字节），磁盘
   占用按段数×64MiB 计，不按有效帧字节数。
3. 探针纪律：链/压缩阶段的增量向量必须与基集**不相交**（复制基向量
   会以距离 0.0000 平局抢走自查询 top-1，smoke 踩过）。

## 1. 构建（阶段 A：build）

摄入（wrapper 真实路径，batch 256，CP 64MiB，安静机 12:45 开跑）：

  ——对照 8192 条时的 27.4k/s：差值几乎全部是 seal 停顿（下表），
  D5"写不被索引构建阻塞"在 1M 依然成立（无索引构建期长阻塞，
  最长单次等待=最大压缩停顿）。
- **seal 46 次 = 34 轻 + 12 压缩**（3.07GB WAL / 64MiB ≈ 48 理论值，
  每 4 次一压缩，与 3×64MiB 轻档累计+256MiB 阈值精确一致）。

| 档 | 次数 | 停顿 p50 | 停顿 max | 备注 |
|---|---|---|---|---|
| 轻（Rotate+manifest v2） | 34 | 175ms | 395ms | 随 N 缓涨（8192 条时 p50 10.8ms） |
| 压缩（v6 快照+森林+Reset） | 12 | **11.47s** | **26.27s** | 停顿随 N 线性：0.52s→2.4s→4.0s→5.8s→8.5s→9.6s→…→26.3s |

  ~150s，占摄入墙钟 ~88%。**运营结论：1M 级运行中压缩档停顿是十秒
  级**；256MiB 阈值下每 ~320MiB WAL 触发一次。这是"记录并建议"级
  结构信号（候选：压缩档异步化/分段写、或阈值随 N 缩放），本会话
  不修。
- ingest 期间车道并发打包 ~30.7k（≈180/s），drain 起点 overlay
  970,751。

可忽略"而非可测的配对差。微基准本身的 -51~62% 结论不受影响
（那是 sub-ms 工况下的主导项）。

## 3. 重启四工况

公共背景：阶段 A 的 Close 是**轻量档**（315ms，保留 146MiB<256MiB），
快照/森林停留在摄入期最后一次压缩边界（v-3781/LSN 3781，v.vec
2.80GB，mtime 比重启时刻旧 11.5h）——这是突发摄入库 Close 的常态
形态，也是四工况里最坏一况的前提。

| 工况 | open | overlay-at-open | ready（收敛） | 说明 |
|---|---|---|---|---|
| **B1 冻结积压重开**（最坏：轻量 Close 后重开突发构建库） | 6.074s | **970,751**（99.7% 库） | **2h57m30s** | 见下 |
| **B3-reopen 新鲜压缩后重开**（意外收获的 mode-A 前菜） | 7.596s | **2,047**（尾） | 即刻 | B2 bulk 压缩刷新森林后的重开 |
| **B4 保留链重放**（mode B：base+链） | 7.201s | 45,567（链向量+尾） | **3m9.2s**（238.1/s） | manifest retainFrom=98，链含 bulk+43,520 向量帧 |
| **C3 纯森林加载**（mode A：链空） | open **8.728s** | **511**（纯尾） | **0s**（Open 即就绪） | v.vec 3.16GB；红线 ✓ 裕度 ~68x |
| **D 无森林重建** | open **5.29s** | **1,001,471**（全量背填） | 有界 30m：**126.2/s**；全收敛投影 **≥102.3min**（下界） | 同工作量参照：阶段 A 排水 3h17m40s（同机同车道 970,751 条） |

### B1：冻结积压重开（1M 级关键发现）

- **发现（直测）**：森林缓存在压缩时刻冻结的是"段+overlay **整体**"。
  突发摄入（40s 吃完 1M）+ 车道追赶期间，最后一次运行中压缩把
  **970,751 条未打包向量**冻结进 v.vec；轻量 Close 不刷新森林。重开
  后：open 仅 6.074s（森林挂载+链重放很快），但 overlay 原样恢复
  970,751 条——**ready 2h57m30s，重付了原构建排水（3h17m40s）的
  97%**。
- **结论**：v0.11.2 保留式 WAL 的 256MiB 阈值界住的是**重放字节**
  （open 侧 6s/7s），不是**重打包工作量**（ready 侧 ~3h）。冒烟级
  发现（85536=冻结积压，两次独立复现）在 1M 直测完全复现。
- **运营建议（记录不修）**：突发摄入近 1M 的部署，关停前若在意重启
  就绪时间，应在收敛后触发一次压缩（如 bulk 卷过 256MiB 阈值）或
  等车道收敛再关；候选结构项=压缩档只冻结已打包段（overlay 走链
  重放）或 Close 时按积压量分档。

### B2/B3/B4：受控三段链

- B2 bulk 256MiB（25.8s，2 轻+1 压缩）把森林刷新到**已收敛态**（尾
  overlay 2047）；B3 重开即 **open 7.596s + overlay 2,047 + 即刻就绪**
  ——这本身就是 1M 级"新鲜森林加载"的直测（mode A 的等价形态）。
- B3 链摄入 43,520 向量（2.121s，3 个轻 seal，无压缩），Close 轻量
  1.401s；拷贝 6.82GB（1.92GB/s）。
- **B4（mode B 直测）**：重开拷贝，open 7.201s，overlay-at-open
  45,567（=链向量 43,520+尾 2,047，重放把压缩边界后的全部帧回灌
  overlay），ready 3m9.2s（238.1/s 重打包）——**链重放的真实成本
  在排水不在打开**；45k 级链 ≈3 分钟，与链字节成正比。
- 正确性：B1/B4 探针自查询全过（top-1=自身键，距离 ~0）。

### C：纯森林加载（mode A，链空）

- C1 排水链库积压（B3 遗留 45,567+尾）；C2 bulk 128MiB（23.4s）触发
  压缩：全量快照+新森林（v.vec **3.16GB**，含 B 阶段链向量后全库
  1,044,991 条）+ Reset 清链。
- **C3 直测（mode A）**：拷贝重开，**open=8.728s，overlay-at-open=511
  （纯尾），ready=0s**——Open 返回即收敛（森林挂载自带已打包段+尾
  overlay，无重放、无重打包）。加载带宽 ~0.36GB/s（v.vec 3.16GB/
  open 墙钟，含快照与链残余帧的 I/O）。
- **红线判定（1M 重启加载 >10 分钟）**：8.7s，裕度 ~68x，**✓ 远低于
  红线**。100k 时代 922.9x 加速比的形态在 1M 完整保持（对照 B1 的
  2h57m 与 D 的重建）。
- 正确性：探针自查询过（top-1=自身键）。

### D：无森林重建

从 `-asbuilt`（阶段 A 收官态的 shell 快照，n=1,001,471）拷贝、删
v.vec、重开：

- **open=5.29s，overlay-at-open=1,001,471**——背填把全库回灌 overlay
  （State.Add O(1)），Open 很快、真相在排水。
- **有界 30 分钟窗**：打包 227,328 条 = **126.2/s**（活跃窗 272.8/s，
  合并窗 0/s 交替——与阶段 A/B1 曲线同形）。
- **全收敛投影 ≥102.3 分钟（算术下界）**；级联合并另加。以同机同
  车道同工作量的完整直测为参照：阶段 A 排水 **3h17m40s**（970,751
  条）与引擎级 1M 全量构建 3h38m15s（2026-10-19）——重建现实落点
  **~3-4h**，下界只是下界。
- 对照：mode A 加载 8.7s vs 重建 ~3h——**无森林的代价≈三个数量级**
  （100k 时代 922.9x 的形态在 1M 保持甚至放大）。v.vec 的存在价值
  在 1M 级是决定性的。

## 4. 内存（HeapAlloc after explicit GC 口径）

- **graph-alone（集成口径，门 2a 遗留线的 1M 直测）**：
  **HeapAlloc 6.59GB**（HeapInuse 7.32GB，HeapSys 34.32GB——GC
  余量 ×2.3，GOGC=100 默认）。全量在场（graph+参照+fixture）
  HeapAlloc 9.77GB。
- 原始向量字节 1,001,471×768×4B = 3.08GB → **集成常驻放大
  6.59/3.08 ≈ 2.14x**。构成：props 库一份（节点携带 emb，3.08GB）+
  森林一份（segment 内向量 3.08GB）+ 图拓扑/键表 ~0.4GB——两份向量
  是数据模型决定的（声明式 props + 索引副本），不是泄漏。
- 对照 10k-100k 实测的 State 级放大模型（1.12-1.46x）：**外推 1M
  应为 ~3.4-4.5GB（State 口径），集成口径无外推模型**。集成 2.14x
  与 State 模型不可直接比（口径不同：多一份 props 拷贝）。State 级
  1M 放大无法事后从本跑剥离（参照与 fixture 同进程、nil 化次序限
  制）——诚实记录：State 级 1M 放大仍无直测，回归守卫
  （TestStateNoPhantomRetention）继续承担。
- GC 成本：全程 NumGC=149，PauseTotal **16.3ms**（平均 0.11ms/次），
  GCCPUFraction 0.0002——**GC 停顿在 1M 构建全程可忽略**；spike 时代
  "1M×768 ≈ 3GB 常驻，Go 标记辅助会进 p99"（spec §12 GC 注记）的
  担忧在实测中未兑现（两阶段打包后垃圾量可控，p99 查询 6-17ms 无
  GC 毛刺尖峰可见——max-of-50 未见异常离群）。

## 诚实备注

1. **门控排队 dominates 墙钟**：本机 16:00-00:15 持续有用户/并行
   会话负载（crema、mediaanalysisd、另一基准会话 100-800% CPU），
   阶段 B 排队 ~8h（安静门控纪律不动摇）；所有记录数字均来自门控
   通过后的独占窗口。
2. **drain 曲线受合并窗口支配**：0/s 长窗口（最长 >30 分钟）是深层
   级联合并的单次大重建，非停滞（CPU ~200% 佐证）；累计速率
   （81.7/s）才是可比口径，窗口速率仅供诊断。
3. **B1 与阶段 A 排水几乎同形**（同 970,751 起点、同合并窗口位置）：
   两条独立曲线互为一致性证据。
4. **p99= max of 50**（协议 #4 同口径）：样本量小，绝对 p99 有下偏
   风险；ef64 12.16ms 的超线结论以 p50 8.95ms+max 双口径佐证。
5. **D（重建）为有界窗口+速率投影**（若全跑会再占 ~3h 独占机时）；
   投影是下界（级联合并追加）。引擎级 1M 全量构建 3h38m15s
   （2026-10-19 直测）是同工作量上界参照。
6. **spec §12 的 GC 忧虑未兑现**（PauseTotal 16.3ms/3.5h、
   GCCPUFraction 0.0002）：两阶段打包的垃圾控制有效；该注记可销。

## 复现

```
cd docs/benchmarks/2026-10-23-vector-1m
./run_stage.sh build   8h VECTRA_1M_DIR=/tmp/vectra-1m
cp -R /tmp/vectra-1m /tmp/vectra-1m-asbuilt   # 重建配对输入
./run_stage.sh chain   8h VECTRA_1M_DIR=/tmp/vectra-1m
./run_stage.sh compact 3h VECTRA_1M_DIR=/tmp/vectra-1m
./run_stage.sh rebuild 2h VECTRA_1M_DIR=/tmp/vectra-1m \
    VECTRA_1M_REBUILD_FROM=/tmp/vectra-1m-asbuilt \
    VECTRA_1M_REBUILD_MAX_SECS=1800
```

默认 VECTRA_1M_N=1,001,471、CP 64MiB；完整旋钮见 harness 头注。
