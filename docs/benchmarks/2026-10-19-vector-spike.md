# Vector Phase 0 Spike Report

- 日期：2026-10-19
- 分支：spec/vector-search
- 状态：Phase 0 收尾。500k/1M 长跑被用户中止（转向构建优化）；门 2a 按已有数据条件判定，优化后复测。
- 环境：Apple M5 Pro，单线程，纯标量 Go，Cosine，M=16，EfC=200，种子固定。

## 口径变更（重要）

v1 矩阵的查询集用 `genClustered(n=50)` 生成，只有 1 个簇心——全部查询分布外（OOD），任务被人为变难。10k×768@ef128 探针实测：OOD recall 0.928，分布内 1.0000。修复（0c0cca5）后查询协议为标准 ANN 做法：扰动索引向量。**v1 各行仅作压力上界参考，判定以 v2 分布内数据为准。**

## 门 2a 判定（spec §10.3）

| 线 | 实测 | 判定 |
|---|---|---|
| recall@10 ≥ 0.95 | 100k×768 分布内：1.0000（ef 32–384 全饱和） | ✅（1M 未直测） |
| 查询 p99 < 10ms | 100k×768@ef64：3.08ms | ✅（100k 实测；1M 外推 4–6ms+overlay 压线） |
| 内存放大 ≤ 1.6× | 10k–100k：liveAmp 1.12–1.46×（HeapAlloc after GC 口径） | ✅ |

**结论：条件通过。** 条件：1M 未直测（500k/1M 运行被中止），外推成立但需构建优化完成后复测；构建吞吐是独立红线，见下。

## DefaultC 锁定

0.95 线在 ef=32 即过：c = 32/log₂(100k) ≈ 1.93。取 **DefaultC = 2**。自适应公式 `max(64, c·log2(n))` 在 n ≤ 2^32 内由地板 64 主导。

## 构建吞吐（独立红线，优化立项）

| N×dim | 速率 |
|---|---|
| 10k×768 | ≈80 向量/s |
| 100k×768 | ≈17 向量/s（超线性劣化） |

对标 hnswlib 单线程慢 10–20 倍。后果：持续写入 >17/s 会积压；1M 建图 >30h，重启重建窗口不可用。嫌疑（待 profile 排序）：selectNeighbors 的 O(M·take·dim) 检查、heap 分配、标量距离、双重拷贝。**下一个 session 专项优化，见仓库台账。**

## 修正过程（进仓库前拦截的缺陷）

- 计划 v1：三处编译错误 + 三个度量口径缺陷（审计 REJECT，重写为 v2）。
- 近邻选择 closest-first：聚类召回坍塌 0.52@ef64 → 换 Malkov 启发式。
- `[:0]` 截断幻影驻留 2.46× → nil 丢弃后 1.12×（有回归测试守护）。
- 查询分布缺陷（本文档口径节）。
