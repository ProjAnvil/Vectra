# Vectra 压测结果（2026-10-12，M1 Pro 18 核，vectra-bench）

环境：Apple M1 Pro（10 核 CPU/18 逻辑）、Go 1.27.2、单进程。
方法：幂律 BA 图（5% 回边）+ 度加权参数固定化 + 8 并发 worker × 5s（预热丢弃），
延迟为客户端视角就近排名分位数。数据目录即用即删（gitignore），仓库只留本文件。
复现：`cd server && go run ./cmd/vectra-bench -size <small|medium|large> [-mode http]`。

## 解读

1. **多跳扩展曲线符合理论**：引擎模式 3 跳 p50 从 S 的 7.7µs → M 的 763µs → L 的 7.1ms，
   与"幂律图 3 跳邻域规模随图近似线性增长"一致——高扇出热点使 3 跳邻域覆盖大半图，
   这是多跳查询最困难的样例集（比均匀随机图苛刻）。
2. **L 档全图 BFS ~70ms**：100 万节点/1000 万边的整图遍历（从热点起点）在引擎模式
   约 70ms、p99 103ms——满足"依赖图谱全量影响面分析"的交互级体验。
3. **HTTP 开销**：one-hop/最短路这类轻查询 p50 增加 ~150-250µs（JSON+HTTP 往返），
   QPS 降一个数量级但仍以万计；重查询（全图 BFS）的开销占比可忽略。
4. **写入路径**：引擎直写 950 万边/s；经 raft+HTTP 注入 130 万边/s（L 档 10M 边约 8s），
   发布器节流（SealInterval）是服务模式注入的主要成本来源——大图热替换的预期行为。
5. **零错误**：全部负载 err=0（6 配置 × 6 负载 × 8 并发），含 http 模式发布期间的
   并发读——免锁读与热替换声明经受住了压力。
