# v0.11.2 性能 hotfix：范围与证据（2026-10-22）

分支 hotfix/0.11.2（基于 v0.11.1）。业主裁定：原计划 v0.12 的性能项并入
0.11.2 patch 系列。方法不变：先测量，后动手。

## 项 1：帧骨架编码 —— 关闭（数据不支持）

微基准（internal/wal/wal_v2_bench_test.go，512×768 批）：

| 部分 | 耗时 | 占边界比 |
|---|---|---|
| 批边界整体（含 fsync） | 6.8-7.5ms | 100% |
| 纯编码+写（ModeInterval） | 2.1ms | 30% |
| 其中 JSON 骨架 marshal | **0.3ms** | **4%** |

fsync ≈ 5ms 是耐久性底线。骨架二进制化最多赚 4%。**推迟**，基准文件留档。

## 项 2：wrapper Close 阻塞向量排水 —— 已修（9c8c8fb）

证据链：A.2 复测 wrapper Close 9.3s vs 直写 Close 251ms（overlay 相同）。
机制：merger 的 drainVectors 单次唤醒最多打 8 chunk（16K 向量，单线程
HNSW 9-18s），quit 只在 select 分支间可见，Close join mergerDone 等完整
趟。向量收敛按 spec D10 本就是惰性（不排完正确，重开后台补）。

修复：drainVectors 按 chunk 边界检查 quit。本机（比 A.2 机慢 ~4x）：
Close **39.2s → 3.0s**（= 一个在途 chunk），重开 overlay 6144/8192 = 恰好
3 个被放弃的 chunk（行为断言，时序无关，RED/GREEN 齐备）。审查通过。

业界交叉验证（DeepWiki）：Weaviate 关机走带 deadline 的 context，操作不
允许无限阻塞；Postgres fast/immediate 分级；Redis SAVE/NOSAVE 可选。
阻塞式全量排水是异类，修复方向与业界一致。

## 项 3：cypher 结果行分配（绑定 map 克隆）—— 进行中

v0.11.1 遗留分解：244 allocs/query 里 ~4/行 来自行模型（绑定 map 全量克
隆 + 增长）；~2/行是公共契约（[]map[string]any）。本项消除克隆部分，不动
公共契约。方案：copy-on-write 绑定（共享父 map，写前复制）。

## 项 4：增量 checkpoint —— 已交付（保留式 WAL 链）

**裁定与落地**：业主并入 0.11.2；下方 delta-文件草案被**保留式 WAL 链**取
代（轻量档 Rotate + manifest v2 `RetainFrom`，压缩档按 256MiB 保留字节写全
量；store v6 绊线 + 陈旧 forest 加载门）。设计与实施计划见
`docs/superpowers/plans/2026-10-22-v0112-checkpoint.md`，实测见
`docs/benchmarks/2026-10-22-v0112-checkpoint.md`：wrapper 默认配置吞吐
10.2k → **27.4k/s**，seal 停顿 p50 119.8 → **10.8ms**，Close 7.4-9.8s →
**~1s**；门 2b 三线与 100k 重启（922.9x）持平。

原调研记录（业界形态对照，保留为证据）：

现状：每次 Seal 写全量快照（O(N)，100k 级 24.4MB，1M 级 ~3GB）。业界调
研（DeepWiki：Qdrant/ArangoDB/Weaviate）共识形态：

- **Qdrant**：段式存储 + `segments_manifest.json` 列活段（Active/
  UnderConstruction/Optimizing/Retiring）；删除走墓碑位图，段负载永不改
  写；合并期 ProxySegment 提供 CoW。
- **ArangoDB(RocksDB)**：memtable→SST 增量刷；`max_total_wal_size` 触发
  最老 WAL 对应 memtable 的刷盘；恢复只从最后刷盘 seq 起重放 WAL 尾。
- **Weaviate**：LSM 段 + HNSW commit log；按层/大小触发 compaction；备
  份快照 = 暂停 compaction + 刷 memtable + **硬链接不可变段**（零重写）。

适配 Vectra 的方案（**delta 快照链**，最小重构）：checkpoint 写增量快照
（只含上次快照后层里的记录——层本来就是现成的增量载体）；manifest 引用
base + 有序 delta 链；加载 = base + delta 链 + WAL 尾（全部走现有层重放
机制）；链长或总量超阈值（如 4 段或 >50% base）时压回全量（今天的路径）。
forest 文件不变（水位仍是 checkpoint LSN）。涉及 store v6 + manifest 模式
+ 加载序——独立 SDD 弧（spec+计划+约 6-8 任务），单列排期。
