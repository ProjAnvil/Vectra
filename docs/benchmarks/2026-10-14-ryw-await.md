# RYW Await 基准报告（v0.5.0 验收）

Date: 2026-10-14 · Branch: `feat/txn-group-commit` · Apple M5 Pro（APFS，dev 级存储——见"边界"）
Config: S 档 / http / 16 worker / 10s / seed 42 · 对照基线：v0.4.0（`2026-10-13-oltp-txn.md`：txnsi 542.4、txnser 556.2）

## 变更

读己之写礼仪从客户端 10ms 轮询 `GET /v1/stats` 改为 `GET /v1/await?seq=N` 长轮询（服务端挂起至发布，单次 RTT 返回）。诊断依据见 TxnGroup spec §4.2（Task 0b）：RYW 等待占 p50 的 42%，其中 ~10ms 为纯轮询量化。

## 结果（3 次运行）

| run | txnsi TPS | txnser TPS | txnsi p50 | rywWait（txnsi） | commit | read |
|---|---|---|---|---|---|---|
| 1 | 807 | 783 | 19.13ms | 3.05ms | 16.08ms | 0.71ms |
| 2 | 862 | 848 | 17.84ms | 3.07ms | 14.80ms | 0.71ms |
| 3 | 870 | 836 | 18.02ms | 3.16ms | 14.60ms | 0.64ms |

对照 v0.4.0：**txnsi +56%（542→~846）、txnser +48%（556→~822）；rywWait 11.1ms → ~3.1ms（-72%）；p50 26.5ms → ~18.3ms（-31%）**。

## 验收判定（spec `2026-10-14-ryw-await.md` §4）

- rywWait ≤5ms：**3.0-3.2ms ✓**
- TPS ≥750：**807-870 ✓**
- p50 下降 ≥15%：**-31% ✓**

## 归因与边界

rywWait 剩余 ~3ms = 发布滞后（小图 clone+Seal ~1-3ms）+ 单次 HTTP RTT——轮询量化已消除。commit 相位保持 ~14.5-16ms，由 dev 机 fsync 主导（bolt StoreLogs ≈ 7ms/次，批大小无关，Task 0b 微基准）——**本特性不动它，按设计**。下一个吞吐杠杆是 Linux 级存储重定基线（生产 NVMe fsync 0.2-1ms → 批周期 ~1-3ms，预估 TPS ~4,000+，届时再评估是否需要任何服务端攒批——TxnGroup spec §4.2 的撤回依据）。

原始输出见会话记录；复现：`make bench SIZE=small MODE=http WORKERS=16 WORKLOADS=txnsi,txnser DURATION=10s`。
