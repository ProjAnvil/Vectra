# Vectra v2 Spec：服务模式（Raft 复制）+ 模块重构 + 工程化加固

日期：2026-10-12 · 状态：草案（待子代理审计） · 输入：PM 竞品调研报告、Raft 选型调研报告（本对话）

## 1. 背景与定位重申

Vectra 是 Go 嵌入式内存图引擎，定位"企业依赖图谱"（10 万~1000 万边），v1 已交付：无指针 CSR、层同步并行 BFS、写入侧 SCC 压缩、双向最短路径、单文件快照、93 项测试。

竞品调研的核心规律：**所有嵌入式图产品（Kuzu、CozoDB、SQLite）都没有内置复制/集群；Raft 只存在于 server 产品（Neo4j/Memgraph/Dgraph/TuGraph）。** 因此 v2 的分布式策略采用 rqlite/DQLite 先例——**引擎核心保持零依赖不可变契约，Raft 复制作为独立模块包住引擎**，宿主可以选择只用引擎（嵌入）或引入 server 模块获得多副本基础服务能力。

## 2. 目标（本轮交付）

1. **模块重构**：根包从"杂烩"拆为清晰分层——`internal/engine`（密封快照与状态）、`internal/traverse`（算法）、根包（门面 API），行为零变化（现有 93 项测试不改断言全部保持绿）。
2. **server 模块**（独立 Go module `vectra/server`）：hashicorp/raft v1.8.0 + raft-boltdb/v2 v2.4.2 实现三节点可容错集群——leader 选举、写复制、leader 宕机重选、日志回放/快照恢复；HTTP JSON API（stdlib net/http，零新增 API 框架依赖）。
3. **热替换发布**（blue-green）：FSM 维护可写 live 图，后台发布器克隆→Seal→原子指针交换，查询永不中断、免锁并发读声明保持。
4. **引擎小能力**：`Clone()`（发布器依赖）、节点属性谓词过滤 `WithNodeFilter`、Seal 期字符串属性索引 `IndexProperty` + `LookupByProperty`、快照格式 v2（CRC32 完整性校验，读端兼容 v1）。
5. **工程化**：覆盖率测量并补缺口（引擎+server ≥85%）、server 集群混沌集成测试、modern-go 规范检查、最终代码 taste 审查。

## 3. 非目标（明确不做，理由来自竞品调研 C 档）

- **核心内置 Raft**：会把部署拓扑绑进库，杀死单文件快照简单性。Raft 只活在 server 模块。
- **在线写/delta-CSR**：推翻"无指针 CSR + 免锁并行遍历"两大赌注；依赖图是可再生的派生视图，热替换已满足分钟级新鲜度。
- **成员移除/在线缩容**：v2 支持加入（join/AddVoter），不支持 RemoveVoter——缩容走运维文档（重建集群）；**TLS/传输加密**、**多 graph 命名空间**同属 sidecar/后续版本。
- **删除操作**：v2 batch 只有 upsert（依赖图谱语义：节点/边只增，属性可更新）。增量 patch 接口留 B 档。
- **分片/磁盘溢出**（>1000 万边）：与"小图全内存"冲突。
- **查询语言**（GQL/Cypher 子集）：v2 只保证结果可序列化 + 错误码规范，解析器是独立 parser 包的未来挂载点。
- **PageRank/WCC/k-core 算法内核**：PM 排序 A4，本轮让位于架构与可靠性，v2.1 交付。
- **认证/多租户**：sidecar 层职责。

## 4. 架构

### 4.1 模块布局（重构后）

```
vectra.go / query.go          门面：Graph、Node/Edge、选项、链式 API（薄，委托 engine/traverse）
internal/csr/                 CSR 邻接（不变）
internal/dag/                 Tarjan/凝聚图/层级（不变）
internal/engine/              密封快照 Snapshot（CSR/SCC/成员表/标签）+ Seal 流水线 + 属性索引 + Save/Load 胶水
internal/traverse/            BFS（串行/并行）/可达性/最短路/Cycles，输入 *engine.Snapshot
internal/store/               快照编解码（v2: +CRC32 尾部，v1 读兼容）
server/                       独立 module：module vectra/server（replace vectra => ../）
  node.go                     Node：组装 raft、发布循环、生命周期
  fsm.go                      GraphFSM：Apply(batch)/Snapshot/Restore + 发布器
  batch.go                    Batch 变更集定义与 gob 编解码（写日志格式）
  api.go                      HTTP JSON API（/v1/*）+ expvar 指标
  node_test.go                进程内 3 节点集群混沌测试（InmemTransport）
  api_test.go                 HTTP 端点测试
```

核心模块零第三方依赖（go.sum 保持不存在；其 go 指令维持现状）；server 模块为独立 go.mod，仅依赖 hashicorp/raft v1.8.0、raft-boltdb/v2（版本理由：隔离依赖树，核心用户零成本）。选型依据：单模块无 transport 拆分（v1.8.0 实测核实）、InmemTransport 全功能可做进程内集群测试、FSM 三方法与整图快照模型对口；备选 go.etcd.io/raft/v3（需自研传输+事件循环，净负债）；dragonboat 停滞+Pebble 依赖重，排除。

### 4.2 server 数据面

```
客户端 --POST /v1/batch--> 任意节点
  ├─ 非 leader：503 + Retry-After + X-Vectra-Leader 头指向 leader
  └─ leader：校验 batch → r.Apply(gob(batch)) → raft 复制到多数派提交
        → FSM.Apply（各节点确定性回放到 live 可写图，标记 dirty）
        → 发布器（每节点本地）：dirty 且距上次发布 ≥ SealInterval
              → RLock 下 Clone live → 解锁 → Seal 克隆 → atomic.Pointer 交换 → 指标
查询（GET/POST /v1/query 等）→ 本地 published 快照（免锁并发读，新鲜度 ≤ SealInterval）
raft Snapshot() → Persist：克隆 live → Seal → store v2 字节流写 sink（写时 CRC32）
raft Restore(rc) → 读字节流（校验 CRC）→ 重建 live → Seal → 发布
```

一致性语义（README 明示）：写线性一致（raft 提交即返回），读有界过期（bounded staleness = SealInterval）；读己之写可通过 POST 后轮询 stats 对账（v2 不提供 Barrier 端点，留接口）。默认 SealInterval=2s（图小于 10 万边时每 batch 后立即发布）。

### 4.3 集群组建、目录布局与地址映射

**目录布局**：`{DataDir}/raft.db`（raft-boltdb，LogStore+StableStore 同实例）；
`{DataDir}/snapshots/`（raft FileSnapshotStore，生产）；
`{DataDir}/meta.json`（本节点 NodeID/HTTPAddr/RaftAddr）。

**组建协议**：首个节点 `Join==""` 且无既有 raft 状态 → `BootstrapCluster`（单节点）；
其余节点 `Join=seed 的 HTTPAddr` → 启动 raft（不 bootstrap）→ `POST /v1/join` 到 seed
（body: `{nodeID, raftAddr, httpAddr}`）→ seed 调 `AddVoter` 并把新节点三元组登记进本地注册表，
响应携带全量注册表（join 时一次性同步）。**防脑裂约束**：`Join!=""` 的节点绝不 bootstrap；
两个空 Join 的新目录各自 bootstrap 属于运维错误（与 etcd initial-cluster 同类），
README 运维章节明示。

**Leader 重定向**：每个节点维护 `map[raftAddr]httpAddr` 注册表（初始 peers + join 扩散）。
非 leader 收到写请求 → `503 + Retry-After` + `X-Vectra-Leader: httpAddr`（未知则省略头）。
注册表是尽力而为的最终一致（v2 规模 3~5 节点足够；RaftAddr 精确性以 raft 为准，
HTTPAddr 仅作提示）。

**重启恢复与就绪门**：raft 打开 → FSM 回放已提交日志（此间 live 图逐步重建）→
发布器执行首次发布（不等待 SealInterval）→ `Ready()` channel 关闭。HTTP `/v1/health`
在 Ready 前返回 503；查询端点在 Ready 前同样 503（`ErrNotReady`）——消除启动期
无界过期的洞。

### 4.4 关键接口契约

```go
// engine（internal）
type Snapshot struct{ /* csrF/R, sccOf, cond/R, sccLevel, 成员表, labels, nodes, edges, 索引 */ }
func Seal(nodes []Node, edges []edgeRec, labels []string, indexKeys []string) (*Snapshot, error)
func (s *Snapshot) Clone() *Snapshot  // 深拷贝未密封原料 → 重新 Seal（server 发布器用）

// 根包新增
func (g *Graph) Clone() *Graph                         // 未密封深拷贝（Seal 前后均可）
func (g *Graph) IndexProperty(key string) *Graph       // Seal 前注册索引键（字符串值）
func (g *Graph) LookupByProperty(key, value string) ([]Node, bool) // 索引命中；key 未注册返回 ok=false
func WithNodeFilter(pred func(Node) bool) BFSOption     // 标记新节点时谓词过滤
func (q *Query) Where(pred func(Node) bool) *Query      // 链式等价物

// server（独立 module）
type Config struct{ NodeID, HTTPAddr, RaftAddr, DataDir string; Join string; SealInterval time.Duration }
func New(cfg Config) (*Node, error)      // 恢复或引导（首个节点 BootstrapCluster；Join 走 AddVoter）
type Batch struct{ Nodes []NodeUpsert; Edges []EdgeUpsert }
func (n *Node) Apply(ctx, Batch) error   // 本地非 leader 自动转发 leader
func (n *Node) Close() error
func (n *Node) Published() *vectra.Graph // 原子快照视图
func (n *Node) IsLeader() bool
```

### 4.4 HTTP API（/v1）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | /v1/batch | 写入变更集（leader only，非 leader 503+Retry-After+X-Vectra-Leader；未就绪 503） |
| POST | /v1/join | 登记新节点并 AddVoter（seed 节点执行，携带注册表响应） |
| GET | /v1/stats | Stats + leader/term/publishedAt |
| GET | /v1/nodes/{key} | 节点详情 |
| GET | /v1/neighbors?key&dir&label | 一跳邻居 |
| POST | /v1/query | `{from[], labels[], direction, maxDepth, nodeFilter? 不支持——谓词不序列化}` |
| GET | /v1/reachable?from | 可达集 |
| GET | /v1/path?from&to | 最短路径 |
| GET | /v1/cycles | 循环依赖清单 |
| GET | /v1/health | liveness（含 leader 状态） |
| GET | /debug/vars | expvar 指标（applied_batches/seals/queries/leader_changes） |

错误体统一 `{"error": {"code": "...", "message": "..."}}`，码表：`NOT_LEADER`、`NODE_NOT_FOUND`、`VALIDATION`、`SEALED`、`TIMEOUT`。

### 4.5 快照格式 v2

v1 布局不变，版本号 1→2，文件尾追加 4 字节小端 CRC32（IEEE，覆盖 header+body）。Decode：v2 校验失败报错；v1 无尾按无校验接受（读兼容）。SaveFile 写临时文件 + fsync + 原子 rename（备份完整性，PM A5）。

## 5. 测试与验收

1. **重构不动行为**：现有 93 项测试（含 SNAP ground-truth、属性对账、race）零断言修改全绿。
2. **引擎新功能 TDD**：Clone/属性索引/谓词过滤/CRC v2（含 v1 读兼容、坏 CRC 拒绝、rename 原子性）。
3. **server 集群混沌（InmemTransport 进程内 3 节点）**：
   - T1 引导与复制：bootstrap→选主→写 batch→三节点 published stats 一致；
   - T2 leader 宕机：关 leader→新 leader 产生→继续写→复制成功；
   - T3 日志回放恢复：旧 leader 携带 raft 状态重启→追平（复用 InmemStore 生命期模拟磁盘）；
   - T4 FSM 快照恢复：Persist→Restore 到新 FSM→图一致；
   - T5 发布新鲜度：写后有限时间内 published 反映变更（SealInterval 上界）。
4. **HTTP API 测试**：全端点 + 错误码 + 非 leader 重定向头。
5. **覆盖率**：`go test -cover ./...`（核心）与 server 模块各自 ≥85%，数字写进 README。
6. **modern-go**：对全部新改文件跑规范 CLI 清单并按建议修改。
7. **taste 审查**：全部完成后子代理代码审查（架构边界/命名/错误处理/并发正确性），按发现修复。

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| raft v1.8.0 要求 go ≥1.25、raft-boltdb v2.4.2 要求 ≥1.26，CI 若钉 1.24 会断 | server 模块独立 go.mod（1.26）；核心模块保持 1.24 不受影响；备选降级组合 v1.7.3+v2.3.0（API 兼容） |
| 发布器 Clone 大图时写停顿 | Clone 在 RLock 下拷贝切片与 map（O(n)，memcpy+指针追踪级）；Seal 在锁外。Props map 共享引用，靠 engine 的"替换不修改"契约保证安全（见 4.3） |
| Followers 回放容忍坏 batch（raft 提交后不能失败） | **权威校验在 FSM.Apply 内**（各节点独立、确定性）；leader 准入校验仅为 UX 前置检查；回放端跳过无效项并计数进指标 |
| gob 格式无版本 | Batch 结构内嵌 Version 字段；演进规则：只加字段（gob 兼容） |
| 坏快照在 CRC 校验前触发超长分配 | v2 Decode 先整体读入文件（受文件实际大小约束）再校验 CRC、再解格式；u32 长度不再直接决定分配 |
| raft 默认超时拖慢混沌测试 | 测试用独立 Config：tick 20ms、ElectionTick 12、HeartbeatTick 2；SnapshotInterval 30s、SnapshotThreshold 8192、TrailingLogs 8192；T2 宕机=断开 InmemTransport（非优雅 Close），另设优雅 Close 用例 |
| Close 时序 | sync.Once 幂等：停发布器 → raft.Shutdown → 关 bolt → 关 HTTP |
| raft-boltdb v2.4.2 传递依赖待核实 | 实现期用 `go mod graph` 验证（调研报告称 bbolt v1.4.1，审计称已归档的 boltdb/bolt v1.3.1，矛盾）；不可接受则回退 v2.3.0 |
| 读端最终一致造成用户困惑 | README 语义章节 + /v1/stats 暴露 publishedAt 便于对账 |
