# Vectra Go Code Audit — 2026-11-01

Scope: main@3ec4aa8, all three modules (`github.com/projanvil/vectra`, `server/`, `mcp/`).
Axes: (1) departures from the Modern Go Guidelines for Go 1.27, (2) architecture-level code smells.
Constraints respected throughout: the engine's hot paths are allocation-gated (exact alloc-count tests, zero-alloc reads) and the WAL/store bytes are cross-version wire contracts. Findings that would trade those properties away are marked as such and rejected or gated behind a measured A/B.

Method note: this pass was performed read-only via direct file reads; the guidelines CLI could not be executed in the audit environment (shell unavailable), so guideline IDs below are mapped against the provided authoritative list and the tool's known semantics. Line numbers are from the audited commit.

Coverage: full reads of the root package (vectra.go, merge.go, cypher.go, cypher_write.go, changeset.go, view.go, traverse.go, query.go, options.go, vectra_vector.go, writer_hook.go, writer_hook_release.go, race_enabled.go), internal/{wal, delta, engine, store, traverse, writer, cypher(lexer+ast)}, server/{api.go, fsm.go(1-400), go.mod}, mcp/{server.go, go.mod}. Partially covered: internal/cypher parser/executor bodies, internal/{vector, vecbin, csr, dag, fixture}, rest of server/ (node/raft/publisher/auth/backup/cli/bench), all `_test.go` files.

## 1. Executive summary

The codebase is in notably good health for its age and complexity. The modern-idiom baseline is high and current: `any` everywhere, builtin `min`/`max` on hot paths, `for w := range workers` (range-over-int), `wg.Go` (Go 1.25+ WaitGroup.Go), `atomic.OrUint32`, `atomic.Pointer/Bool/Int64` types, `slices.*`/`maps.*` in broad use, method+wildcard `http.ServeMux` patterns, `errors.Join`, `errors.Is`-based sentinel discipline with documented unwrap chains. Wire-format code (internal/wal, internal/store) and allocation-gated hot paths (internal/traverse, engine lookups) correctly favor manual loops and documented byte layouts; several "duplicated" loop pairs there carry explicit measured rationale (the A1 interface-hop regression, the B2 allocation findings) and should be left alone.

The real maintenance drag is concentrated in three places. First, **vectra.go has grown to 4,102 lines** holding at least seven distinguishable subsystems (three-source reads, writer mirrors/absorption window, unique-constraint registry, WAL recorder + Open recovery, tiered checkpoint machinery + async compact flight, snapshot I/O, property lookups) — the repo itself already established the extraction convention (vectra_vector.go, query.go, merge.go), so this is drift, not philosophy. Second, the **changeset-apply loop exists in four copies** (root replay, internal/writer, server FSM, MCP inject) with per-lane error policies that have already diverged once (the v0.16 unique-violation abort reached the server but not MCP, which still silently drops violating node writes with no counter and no error — the exact "silent skip" the server lane documents having replaced). Third, a set of **small duplications** (atomic-file-write ritual x4, goroutineToken x2, race_enabled x3, toFloat/copyProps x2) that are individually trivial but sit on the paths where a future copy-paste is most likely to introduce a checkpoint-correctness or race bug.

No Critical findings. Guideline departures are few and almost all off-hot-path (manual `max`, three `errors.As` sites, C-style loops on cold paths) and safely adoptable.
