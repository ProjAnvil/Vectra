# 1M 实测三项修复 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 修复 1M 直测的三项发现——Close 丢打包成果（B1 2h57m 重付）、压缩档写者停顿 11.5-26.3s、ef64 p99 超预算线的处置。

**Architecture:** 项 1=pack 漂移计数 + 两个 close 形入口的森林条件刷新；项 2=压缩档异步化（写者只 pin 不可变视图，后台写快照+森林字节，manifest 与 WAL 变更全在写者侧完成步：静默→Reset，忙→v2 manifest 重锚+段粒度删覆盖段）；项 3=ef 扫描实验数据落档 + spec 修订。

**Tech Stack:** Go 标准库（零第三方依赖、无 cgo 硬约束不变）。

**Spec:** `docs/superpowers/specs/2026-10-24-1m-fixes-design.md`（含 builder-check 四问裁定）。

## Global Constraints

- 零第三方依赖、无 cgo；gofmt 干净；`go vet ./...` 零告警。
- 快照仍 store v6、森林格式不变；`wal.Reset` 之外新增删除原语必须
  遵守"manifest 先落、只删快照可证覆盖的整段"纪律。
- 公共 API 语义不变：`Seal()` 显式调用保持同步落盘语义；`Close()`
  对调用方仍是"返回即已检查点"。新增导出仅限 writer 包内部用的
  graph 方法（沿用 `RepairAfterRebase` 的先例，注释注明）。
- 英文 commit；每任务独立提交。

## Review Focus

（spec 隐含但无任务测试覆盖、最可能咬人的五类输入；每行测试挂进
 owning task）
1. Close 只走 `Handle.Close`（不调 `g.Close`）的 wrapper 部署——刷新
   必须生效（B1 主场景）。→ Task 2 的行为测试即此。
2. 飞行期间继续 Submit：新增帧的耐久性（Reset 禁删 >L 帧）。→
   Task 5 的忙情形完成步测试断言重开后数据完整。
3. manifest 已落、段删除前崩溃：多余 ≤L 段被 lsn 门槛跳过，重开正
   确。→ Task 3 的 WAL 单测 + Task 5 崩溃窗测试。
4. 写盘失败的飞行：错误浮出到 Close（cpErr 粘滞），不留半写快照。
   → Task 4 错误注入测试。
5. 无 pack 漂移的库 Close：森林 mtime 不变（成本模型不破）。→
   Task 2 的 mtime 断言。
