# v0.12.0 Auth + Full-Text Search Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v0.12.0 with (A) static bearer-token auth for the raft HTTP server and (B) an opt-in bigram full-text index over node string properties with `LookupByContains`.

**Architecture:** Auth wraps the single `http.ServeMux` inside `(*Node).Handler()`, Config-gated so empty config is byte-identical to today; the join protocol reuses the same token (single trust domain). FTS is a fourth index kind: a sorted bigram slice built only at `engine.Seal` (like typed buckets), declared via `IndexFullText(key)`, persisted as declarations only (WAL `IndexDecl.FullTextKeys` + store v7 `FTSKeys` section), and queried through the existing `lookupNodesOf` three-source compensation so correctness under unmerged layers is inherited. Grams never persist and never survive a rebase — they are rebuilt from records at every Seal.

**Tech Stack:** Go 1.27.2 (three modules: `.`, `server`, `mcp` under `go.work`), std-lib only, no new dependencies. Python (httpx) and TS MCP proxies get a 2-line `VECTRA_TOKEN` header each.

**Spec:** `docs/research/2026-10-26-gap-fill-feasibility.md` (§1 鉴权, §2 全文搜索) plus the 2026-10-26 audit verdicts (A1-A8, B1-B7) embedded per-task below. Executors read both.

## Global Constraints

- Go 1.27.2; test/vet/fmt via `make test` / `make vet` / `make fmt` (iterates `. server mcp`). Zero new module dependencies — std-lib only.
- WAL JSON frames stay on the existing `encoding/json` path (do NOT migrate to `encoding/json/v2`; guideline applies to new JSON code only, and these frames are existing code).
- Store evolution rule: **add fields only** (`changeset.go:27-48` gob discipline). This plan bumps store version v6 → v7 because layout changes (new trailing FTS section). Unknown-version decode must keep hard-failing; tripwire tests retarget so v7 is current and v8 is rejected.
- Modern Go (authoritative for new/edited code): `slices.SortFunc`+`cmp.Compare`, `slices.Sorted(maps.Keys(...))`, `any`, `errors.Is`, `strings.Cut`, `for i := range n`, no redundant loop-var copies, **`b.Loop()` for new benchmark functions**, method-aware ServeMux patterns (already used).
- Existing server tests must pass **unchanged** when no token is configured (zero-churn guarantee); same for all root/mcp tests.
- Cypher `CONTAINS` stays scan-based in v0.12 — do NOT wire FTS under it (case semantics differ: `LookupByContains` is case-insensitive, Cypher `CONTAINS` is case-sensitive).
- Bench red lines (release blocker, measured at Task 10): FTS seal overhead ≤ 2x no-FTS seal AND absolute seal ≤ 1.5s AND peak alloc delta ≤ 250MB at 100k nodes / one FTS key. If breached near release: v0.12.0 ships auth-only, FTS moves to v0.13.0 (pre-agreed fallback, no debate).
- Commit style: English, conventional (`feat:` / `test:` / `docs:`), one commit per task unless a task says otherwise. No pushes. No merge to main — the owner decides.
- Branch: `feat/v0.12.0-auth-fts` (already created from main@cd43731).

## Review Focus

1. **Token file edge cases must fail closed** — empty file, whitespace-only lines, unreadable path: `server.New` errors at startup, never silently runs open (a silently-open DB is this feature's worst failure mode). → Tests in Task 1.
2. **Auth-enabled cluster join** — token present on seed but not joiner (or wrong token) → join 401, node stays candidate with the existing stderr warning; token on both sides → cluster forms and replicates. → Task 3.
3. **FTS declaration silently lost across merge/restart** — four `engine.Seal` call sites (+ four test-file call sites), the `store.Encode` Save path, WAL replay, fold union, `unionRecords`: a miss means the index answers until the first merge, then quietly returns `ok=false`. → e2e round-trip tests in Tasks 7-8 (declare → write → Save → Load → still answers).
4. **Store v7 regression** — v6 snapshots must remain readable; `snapshotIsV6` is an equality check (`== VersionV6`, vectra.go:2557) that would permanently skip the light checkpoint tier on v7 bases once Encode stamps v7 — must become `>=`. → Task 6.
5. **Gram-collision false positives and case-semantics split-brain** — gram intersection is a prefilter, values like `"xxabyy bc zz"` carry grams `ab`+`bc` but don't contain `"abc"`: the verify pass is mandatory; and `LookupByContains` (folded) vs Cypher `CONTAINS` (exact) divergence must be cross-referenced in docs/tool descriptions. → Collision test in Task 8; doc notes Tasks 9-10.
